# Calendar Connector — план

## Цель

Один Google-календарь, в который автоматически копируются события из нескольких моих
календарей (с разных Google-аккаунтов). Этот календарь можно расшарить людям
(как минимум «занят/свободен»), например коллегам из `kse.org.ua`.

Требования:

- бесплатный хостинг, «захостил и забыл», без ноутбука;
- всё, что ставится для разработки, живёт внутри папки проекта;
- интерфейс: название календаря, цвет, целевой аккаунт, аккаунты-источники, с кем шарить.

## Выбранная архитектура: Google Apps Script

Код живёт и выполняется внутри Google-аккаунта, в который собираются события (дальше
**целевой аккаунт**). Сервер, оплата и OAuth-клиент в Cloud Console не нужны.

```
аккаунт A ──(shared: все детали)──┐
аккаунт B ──(shared: все детали)──┼──> целевой аккаунт: Apps Script ──> «Объединённый» календарь ──> шаринг людям
аккаунт C ──(shared: все детали)──┘        (триггер каждые 5 минут)
```

- Источники: календари, которые видны целевому аккаунту. Это его собственные календари
  и календари других моих аккаунтов, расшаренные на него с правом «Просмотр всех сведений
  о мероприятиях».
- Синхронизация: триггер по времени каждые 5 минут. Используется Calendar Advanced
  Service, инкрементально через `syncToken`; токены хранятся в `PropertiesService`.
- Интерфейс: Apps Script Web App (`HtmlService`), доступ только у меня.
- Квоты бесплатного аккаунта (~90 минут работы триггеров в день, ~5000 созданных
  событий в день) для личного объёма с запасом.

### Один скрипт на аккаунт («push»)

Календари предметов в KSE (CS101 и т. п.) принадлежат организации: я их вижу, но
расшарить дальше не могу. Поэтому один и тот же код ставится в **каждый** аккаунт-источник:

```
личный Gmail: скрипт (personal) ── свои календари ──────────┐
KSE:          скрипт (kse)      ── мой + календари предметов ──┼──> «Объединённый» (в личном Gmail)
```

- Скрипт читает календари, видимые его аккаунту, и пишет в объединённый календарь,
  доступный ему на запись.
- Объединённый календарь живёт в личном Gmail и расшаривается на KSE-аккаунт с правом
  «Внесение изменений в мероприятия». Это делается через API (`sharing`), руками не нужно.
- id копий включают id исходного календаря, поэтому два скрипта не пересекаются.
- Деплой: `make login|create|push ACCOUNT=personal|kse`, отдельный clasp-проект на
  аккаунт в `.clasp-<account>.json` (в `.gitignore`).

## Модули (`src/`)

| Файл | Что делает |
|---|---|
| `Config.js` | Настройки в `ScriptProperties`: объединённые календари (id, название, цвет, надпись «занят») и их источники (режим `full` / `busy`, префикс); токены синхронизации и статус последнего прогона по каждой паре |
| `Transform.js` | Чистая логика, тестируется в Node: что делать с событием (копия, удаление, пропуск) и тело копии. Убирает участников и напоминания, в режиме `busy` оставляет только время, ставит метку `extendedProperties.private = {ccSrcCal, ccSrcId}` |
| `Sync.js` | Инкрементальное чтение через `syncToken`, копии с детерминированными id (хэш от целевого календаря, исходного календаря и события), исключения серий как экземпляры копии, полная перечитка при `410`, ограничение по времени прогона, удаление копий убранного источника |
| `Api.js` | Обёртки Calendar API: коды ошибок, повтор при лимитах, идемпотентные запись и удаление, список календарей |
| `Calendars.js` | Создание и подключение объединённых календарей, цвет, доступ (`Acl`), ссылки, триггер раз в 5 минут |
| `Ui.js`, `Index.html` | Веб-интерфейс, доступный только владельцу скрипта |

Правила копирования:

- участники не копируются и `sendUpdates=none`, иначе уйдут приглашения от моего имени;
- у копий отключены напоминания, потому что источники уже уведомляют;
- копии помечаются, чтобы не дублировать их и не зацикливаться;
- отменённое или удалённое в источнике удаляется в объединённом календаре.

## Локальная разработка (всё внутри папки)

- `.tools/node`: Node.js из официального архива, без системной установки;
- `node_modules/`: `@google/clasp` для выкладки кода в Apps Script;
- `.secrets/`: токены `clasp` (по одному на аккаунт), лежит в `.gitignore`;
- `.clasp-<account>.json`: clasp-проект каждого аккаунта, тоже в `.gitignore`;
- кэш npm в `.cache/`.

Удаление папки удаляет всё. Снаружи остаются только сами скрипты в Google-аккаунтах.

Команды (`ACCOUNT` по умолчанию `personal`):

| Команда | Что делает |
|---|---|
| `make test` | Unit-тесты и тест синхронизации на фейковом Calendar API |
| `make login ACCOUNT=x` | Вход в Google для аккаунта `x` (браузер) |
| `make create ACCOUNT=x` | Создать скрипт в аккаунте `x` (один раз) |
| `make push ACCOUNT=x` | Тесты, затем выкладка кода |
| `make app ACCOUNT=x` | Ссылка на веб-интерфейс |
| `make open ACCOUNT=x` | Открыть редактор скрипта |

## Подключение аккаунтов

Аккаунты: `personal` (целевой), `kse`, гранты, основная работа, программирование.

Для каждого аккаунта-источника по порядку:

1. **Попробовать расшарить** его календари на личный Gmail: Google Calendar →
   Настройки → календарь → «Открыть доступ пользователям» → личный Gmail →
   «Просмотр всех сведений о мероприятиях». Если получилось, календарь появится в списке
   источников веб-интерфейса `personal`, больше ничего не нужно.
2. **Если нельзя** (календари принадлежат организации, как предметы в KSE, или Workspace
   даёт только «свободен/занят»), ставим скрипт в этот аккаунт:
   1. в этом аккаунте включить Apps Script API: https://script.google.com/home/usersettings;
   2. в интерфейсе `personal` у объединённого календаря дать этому аккаунту доступ
      «редактирование»;
   3. `make login create push ACCOUNT=<имя>`, затем `make app ACCOUNT=<имя>`;
   4. открыть ссылку, выдать разрешения, «Подключить» объединённый календарь, отметить
      источники, «Сохранить».

При первом открытии веб-интерфейса Google покажет «приложение не проверено» (скрипт
мой, не опубликованный): «Дополнительно» → «Перейти».

## Этапы

1. ✅ Каркас: локальный Node и clasp, `appsscript.json`, тесты `transform`.
2. ✅ `sync`: инкрементально, повторы, исключения в сериях, удаление, сброс токена.
3. ✅ Несколько источников, режимы `full` / `busy`, триггер раз в 5 минут.
4. ✅ `sharing`: публичный доступ, доступ людям, ссылки.
5. ✅ Web UI.
6. Живая проверка в `personal`, затем установка в `kse` и остальные аккаунты.

## Решения

- Целевой аккаунт: личный Gmail.
- Рабочий аккаунт `@kse.org.ua` — один из источников. Apps Script в нём уже работал.
  Календари предметов принадлежат организации и не шарятся, поэтому для `kse` нужен
  скрипт в аккаунте («push»).
- Коллегам доступ даётся ссылкой на календарь.
- Объединённых календарей может быть несколько (конфиг это поддерживает), например:
  - **«Мой»**: все источники с полными деталями, только для меня;
  - **«Для KSE»**: те же источники в режиме `busy` (только «Занят»), публичный доступ
    «только свободен/занят» (`Acl` scope `default`, роль `freeBusyReader`). Ссылку на
    него можно давать кому угодно, детали событий не утекут.
