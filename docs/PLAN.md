# Calendar Connector — план

## Цель

Один Google-календарь, в который автоматически копируются события из нескольких моих
календарей (с разных Google-аккаунтов). Этот календарь можно расшарить людям
(как минимум «занят/свободен»), например коллегам из `kse.org.ua`.

Требования:

- бесплатный хостинг, «захостил и забыл», без ноутбука;
- всё, что ставится для разработки, живёт внутри папки проекта;
- интерфейс: название календаря, цвет, целевой аккаунт, аккаунты-источники, с кем шарить.

## Выбранная архитектура: Google Apps Script

Код живёт и выполняется внутри Google-аккаунта, в который собираются события (дальше
**целевой аккаунт**). Сервер, оплата и OAuth-клиент в Cloud Console не нужны.

```
аккаунт A ──(shared: все детали)──┐
аккаунт B ──(shared: все детали)──┼──> целевой аккаунт: Apps Script ──> «Объединённый» календарь ──> шаринг людям
аккаунт C ──(shared: все детали)──┘        (триггер каждые 5 минут)
```

- Источники: календари, которые видны целевому аккаунту. Это его собственные календари
  и календари других моих аккаунтов, расшаренные на него с правом «Просмотр всех сведений
  о мероприятиях».
- Синхронизация: триггер по времени каждые 5 минут. Используется Calendar Advanced
  Service, инкрементально через `syncToken`; токены хранятся в `PropertiesService`.
- Интерфейс: Apps Script Web App (`HtmlService`), доступ только у меня.
- Квоты бесплатного аккаунта (~90 минут работы триггеров в день, ~5000 созданных
  событий в день) для личного объёма с запасом.

### Запасной режим «push», если Workspace режет шаринг

Если админ `kse.org.ua` не даёт расшаривать детали наружу, направление меняется:
объединённый календарь расшаривается на рабочий аккаунт с правом редактирования
(получать внешний шаринг Workspace обычно разрешает). Затем в рабочем аккаунте
запускается вторая копия того же скрипта, которая **пишет** свои события в объединённый
календарь.

## Модули (`src/`)

| Модуль | Что делает |
|---|---|
| `config` | Хранит настройки объединённых календарей в `PropertiesService`: название, цвет, id целевого календаря, список источников и режим для каждого (`full` / `busy`), префикс, шаринг |
| `transform` | Чистая логика (тестируется локально в Node): исходное событие превращается в копию. Убирает участников, отключает напоминания, в режиме `busy` заменяет название на «Занят», ставит метку `extendedProperties.private = {ccSrc, ccId}` |
| `sync` | Инкрементальное чтение источников, создание, обновление и удаление копий, повторяющиеся события и исключения в них, полная пересинхронизация при `410 Gone`, защита от циклов (события с меткой `ccSrc` не копируются) |
| `sharing` | Права доступа к объединённому календарю через `Calendar.Acl`: `freeBusyReader` / `reader` для email-ов или группы, ссылка для подписки |
| `ui` | Web App: список календарей, форма создания и редактирования, кнопка «Синхронизировать сейчас», статус и ошибки последнего прогона |
| `triggers` | Установка и снятие триггера по времени, блокировка через `LockService`, чтобы два прогона не шли одновременно |

Правила копирования:

- участники не копируются и `sendUpdates=none`, иначе уйдут приглашения от моего имени;
- у копий отключены напоминания, потому что источники уже уведомляют;
- копии помечаются, чтобы не дублировать их и не зацикливаться;
- отменённое или удалённое в источнике удаляется в объединённом календаре.

## Локальная разработка (всё внутри папки)

- `.tools/node`: Node.js из официального архива, без системной установки;
- `node_modules/`: `@google/clasp` для выкладки кода в Apps Script;
- `.secrets/`: токен `clasp` (`clasp --auth .secrets/.clasprc.json`), лежит в `.gitignore`;
- кэш npm в `.cache/`;
- `make`-обёртки (`make push`, `make test`, `make deploy`) прописывают локальные пути.

Удаление папки удаляет всё. Снаружи остаётся только сам скрипт в Google-аккаунте.

## Ручные шаги

1. В целевом аккаунте включить Apps Script API: https://script.google.com/home/usersettings
2. В каждом аккаунте-источнике: Google Calendar → Настройки → нужный календарь →
   «Открыть доступ пользователям» → email целевого аккаунта → «Просмотр всех сведений
   о мероприятиях».
3. Войти в `clasp` (команда откроет браузер).
4. При первом запуске выдать скрипту разрешения. Будет предупреждение «приложение
   не проверено», потому что скрипт мой; нужно нажать «Дополнительно → Перейти».
5. Открыть Web App и создать объединённый календарь.

## Этапы

1. Каркас: локальный Node и clasp, `appsscript.json`, тесты `transform`.
2. `transform` и `sync` для одного источника, запуск из редактора.
3. Несколько источников, режимы `full` / `busy`, триггер.
4. `sharing`.
5. Web UI.
6. Режим «push» (если понадобится для `kse.org.ua`).
